# Partline

Клиент поиска автозапчастей на React + Redux Toolkit, JavaScript без TypeScript. Vite, обычный адаптивный CSS, небольшой Express-прокси.

## GitHub Pages — без сервера

Публичная версия — статический React-сайт. Моки находятся в `src/mock.js` и обрабатываются прямо в браузере: поиск не обращается к `/api`, Express или Favorit Parts.

```sh
npm ci
npm run build:pages
```

Публикуется только `dist/`. Относительные пути к ресурсам поддерживают адрес вида `https://user.github.io/repository/`.

Добавлен `.github/workflows/pages.yml`: после push в `main` он запускает тесты, собирает статику и публикует её. В GitHub включите **Settings → Pages → Source: GitHub Actions**. Для другой основной ветки измените `branches` в workflow. Ключ и сервер для Pages не нужны. Из этой рабочей папки публикация не выполнялась.

Обычная `npm run build` также использует клиентские моки. Docker собирает отдельный вариант с `VITE_DATA_SOURCE=server`, который обращается к своему Express-прокси. Эта переменная — только выбор транспорта; ключ в неё не записывается.

## Локальный запуск одной командой (Docker)

Нужен Docker с Docker Compose. Из корня проекта:

```sh
docker compose up --build -d
```

Откройте http://localhost:8080. Node.js на компьютере не нужен, `.env` для запуска не требуется. Образ собирает React и запускает Express, который раздаёт приложение и API. Контейнер работает от непривилегированного пользователя; healthcheck проверяет `/api/health` без обращения к поставщику.

По умолчанию контейнер работает только с моковыми данными (`DATA_MODE=mock`). Это локальная демонстрация в контейнере. Для GitHub Pages контейнер не используется. Клиентский параметр `mode=api` не может переключить такой сервер на поставщика.

Примеры артикулов: `W 914/2` (два производителя), `0 451 103 033`, `OC 384`. Неизвестный артикул даёт пустой результат. Цены, остатки и соответствия аналогов в этом режиме вымышлены.

### Проверка с собственным ключом

Проверяющий разворачивает приложение у себя. Скопируйте `.env.example` в `.env` и задайте:

```dotenv
DATA_MODE=api
FAVORIT_API_KEY=ваш_ключ_покупателя
```

Затем выполните ту же команду:

```sh
docker compose up --build -d
```

Compose пересоздаст контейнер с новыми настройками. Все поисковые запросы теперь идут к Favorit Parts, даже если клиент прислал `mode=mock`. Ошибки поставщика не подменяются моками. Ключ передаётся контейнеру только при запуске: `.env` исключён из Git и контекста Docker-сборки, в браузер ключ не передаётся.

`APP_PORT` в `.env` меняет внешний порт (по умолчанию 8080). Внутренний порт контейнера фиксирован — 3001; `PORT` используется только при запуске без Docker.

```sh
docker compose logs -f app   # логи
docker compose ps            # статус и healthcheck
docker compose down          # остановка и удаление контейнера
```

### Разработка без Docker

Нужен Node.js 22.12+:

```sh
npm ci
npm run dev
```

Интерфейс: http://localhost:5173, прокси: http://localhost:3001. Без `DATA_MODE` сервер использует параметр режима из клиентского запроса. Для реального API при разработке задайте `VITE_DATA_SOURCE=server`, `DATA_MODE=api` и `FAVORIT_API_KEY` в `.env`, затем перезапустите `npm run dev`. Без `VITE_DATA_SOURCE=server` браузер работает с локальными моками.

## Контракт Favorit Parts

[Документация Favorit Parts](https://lk.favorit-parts.ru/static/wsprice.pdf).

1. GET с `number` возвращает `goods`; из них формируется уникальный список брендов.
2. GET с `number`, `brand`, `analogues=on` возвращает деталь и вложенные аналоги.
3. Каждая строка соответствует складу: цена из `warehouses[].price`, остаток из `warehouses[].stock`. Устаревшее `goods[].price` не используется.

По умолчанию используется HTTPS. Адрес можно переопределить через `FAVORIT_API_URL`; автоматического перехода на HTTP нет. Полная проверка поставщика требует действующего ключа. Если в будущем реальный API будет доступен публично, потребуются ограничения доступа и частоты запросов для защиты квоты покупателя.

## Поведение

- Автоматический поиск через 500 мс после ввода и кнопка ручного поиска.
- Отмена запросов при смене артикула или бренда; Redux проверяет requestId и игнорирует устаревшие ответы.
- Отдельные состояния загрузки, ошибок и пустых результатов для обоих шагов.
- Таймаут поставщика 15 секунд, безопасные сообщения при ошибках сети и JSON, повтор запроса.
- Сортировка по цене/остатку и фильтр наличия, таблица на компьютере и карточки на мобильных экранах. Фильтр и сортировка сохраняются между поисками.

## Проверки и production

```sh
npm test
npm run build
npm start
```

После сборки сервер раздаёт `dist` и API на http://localhost:3001. `PORT` меняет порт сервера; при разработке соответствующим образом измените proxy в `vite.config.js`.

Тесты проверяют пустые ответы, ошибки API, дедупликацию брендов и предложений, складские цены и вложенные аналоги. Отдельно проверяются HTTP-прокси, локализация ошибок, сброс Redux, отбрасывание устаревших ответов, отмена запросов и таймер автоматического поиска. Реальные цены/доступ к поставщику требуют действующего ключа.

## Структура клиентского кода

- `src/main.jsx` — подключение React, Redux и CSS.
- `src/App.jsx` — композиция страницы.
- `src/components/PartSearch.jsx` — ввод артикула и выбор производителя.
- `src/components/Offers.jsx` — предложения, фильтрация и сортировка.
- `src/components/RequestState.jsx` — загрузка и ошибки.
- `src/hooks/usePartsSearch.js` — автоматический и ручной поиск, отмена запросов.
- `src/store.js` — состояние Redux и запросы; `src/data.js` — преобразование ответов.

## Автоматические проверки

`npm test` запускает обе группы:

- `npm run test:unit` — 16 проверок данных, состояния Redux, планировщика и HTTP-прокси.
- `npm run test:ui` — 7 интеграционных сценариев React в Vitest + Testing Library + jsdom. Компоненты и Redux настоящие, подменяется только `fetch`. Проверяются автоматический поиск, отсутствие двойного запроса после кнопки, выбор бренда, фильтр/счётчик/сортировка, загрузка/ошибка/повтор, пустые ответы и устаревшие ответы при смене бренда. Дополнительно проверяется полный поиск без единого сетевого запроса для статической сборки. Смена режима проверяется через Redux: в текущей вёрстке нет переключателя режима.

Эти UI-тесты проверяют взаимодействие и DOM, но не геометрию CSS и не живой сервис Favorit Parts. Для этого по-прежнему нужны браузерная проверка и действующий ключ соответственно.

`npm run format` форматирует исходники, тесты и конфигурацию. `npm run format:check` проверяет форматирование без изменения файлов.
